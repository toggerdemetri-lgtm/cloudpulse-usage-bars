- 90项核心/配置测试通过，包含真实旧格式的假DPAPI凭证无损迁移、跨厂商凭证阻断、档案分离、Secret复用条件、损坏空档案、5分钟采样过期规则；43项SDK离线行为测试通过，共133项。
- 新SDK测试覆盖真实采样时间、腾讯原始JSON保留秒精度、Mbps转bit/s、华为byte/s转bit/s、AWS Sum Bytes按60/300秒换算、完整采样桶、完整Agent维度、磁盘分页与部分空盘、缺失不补零、错误脱敏和有界取消。
- 真实窗口集成检查通过：桌面与任务栏往返、左下角及左上角输入命中、松手新HWND及旧窗口销毁、重复请求仅一窗口，保留1.0.6已获用户视觉确认的呈现方案。另验证四厂商表单切换不带入旧密钥、草稿保留、腾讯固定磁盘禁用、华为项目字段、AWS详细监控选择及保存绑定。
- 设置截图使用虚构密钥及临时回调，已人工查看布局；测试未读取真实配置或发送真实云请求。初次原生检查被正在运行的旧版任务栏条遮挡而失败，退出本软件旧版隔离后全部通过，未修改测试以掩盖遮挡。

## 1.0.6 松手后重建显示窗口

- 用户确认1.0.5全新启动时可见，拖动松手后画面消失，但原位置仍能弹出数值提示。物理拖动记录：松手前浮层在 `(0,0)`；松手后桌面子窗口仍在 `(0,0)`、Visible=true、Cloaked=0，四条仍可命中。这排除了越界或窗口隐藏作为完整解释。
- 关键验证限制：此前“颜色条可见”检查实际上只是 WindowFromPoint 命中，不能证明屏幕上有画面，故这些检查现明确称为输入命中检查。
- 故障集中在同一透明WPF窗口反复经历 child→popup→child 后的呈现路径，尚不能断言具体WPF/USER32/DWM内部缺陷。1.0.6仅改为松手后以同一进程内的设置、坐标、模式及缓存创建全新显示窗口，挂载后关闭旧窗口；不重读凭证、不重启轮询。
- 新增实际App窗口生命周期回归：旧版在“松手后应换新HWND”失败；新版通过，并验证保留位置和模式、销毁旧窗口及重复重建请求仅留下一个挂件。测试App跳过正常启动，不加载真实配置或请求云监控。
- 78项核心测试和真实App生命周期集成检查通过；独立只读审阅未发现阻塞缺陷。已备份安装的1.0.5并更新桌面实际程序到1.0.6。
- 用户在1.0.6实际执行“拖离左上角、拖回、松开”后明确确认“松开后仍然能看到”，本次松手后消失问题完成视觉验收。未进一步声称混合DPI多屏或Explorer重启已获人工验证。

## 1.0.5 顶部边缘显示

- 用户实际反馈 1.0.4 拖到左上角不可见；只读记录窗口在 `(-14,-9)`，Visible=true、Cloaked=0。此前系统可见标志和命中检查不足以确认用户实际看见。
- 新增“桌面窗口完整留在屏幕内”的回归，旧版失败（77通过、1失败）。窗口改为192×6逻辑像素，去掉四周透明留白，左上角原点为 `(0,0)`；四条尺寸和间隔不变。左侧副屏仍可使用有效的负虚拟屏幕坐标。
- 78项自动测试通过；真实 IslandWindow 原生集成检查通过，覆盖顶部左侧拖动预览、鼠标命中、松手后桌面挂载与 `(0,0)` 坐标、桌面和任务栏往返、左下角预览及回到桌面。未注入鼠标键盘输入，未读取真实凭证。
- 已生成1.0.5自包含便携程序；用户物理拖动结果尚待确认。

## 1.0.4 左下角拖动回归

- 用户反馈“进入任务栏但尚未松手时消失”。旧版左下角预览会提前在任务栏垂直居中，鼠标可落在预览窗口之外。新增真实命中回归检查在旧版失败，修正后通过。
- 拖动预览改用显示器全屏边界夹取并跟随抓取点，只有松手后才在任务栏居中；仅拖动期间使用接近透明的完整输入面，避免间隙或边缘把输入交给下面的任务栏控件，结束拖动后恢复透明。
- 77 项核心/存储/启动测试通过。额外的真实窗口检查使用真正的IslandWindow，等待绘制后逐根检查WindowFromPoint命中，覆盖预览、任务栏中部、左下角、恢复桌面和托盘返回桌面；桌面模式被普通应用窗口遮挡时按正常行为处理。
- 此前集成测试使用空白窗口，仅验证挂载和尺寸，无法证明颜色条实际可见。本次已替换并保留真实色条回归测试。测试通过证明已修复的输入范围问题，用户物理拖动仍需实际使用确认。

## 1.0.2 自启动与贴边

- 58 项自动测试通过（此前44项＋本次14项）。新增覆盖：按可见范围贴齐四边、边缘吸附、内部位置不变、200% DPI、负坐标副屏、任务栏保留区域、中文含空格路径的启动命令、无效/过长路径、启动项启停且不改动其他值、配置保存失败回滚、旧配置兼容与自启动偏好持久化。
- 自启动集成测试只使用随机 HKCU 测试子键，不修改用户真实的开机启动项；凭证测试继续使用测试假密钥。
- 默认关闭自启动，用户在设置中勾选并保存后开启；命令为带引号的 EXE 绝对路径加 `--autostart`。登录启动静默显示，桌面未就绪时继续重试挂载。
- 修正根因：原先夹取220×24窗口边界，导致可见色条与屏幕边缘之间留下14/9逻辑像素空隙；现在按实际可见区域计算，并缩放到目标显示器DPI。
- 正常 Windows 桌面实测：最终便携程序成功挂载，Win32 读取的原生窗口原点为 `(-14,-9)`；加上色条可见留白后，色条位于屏幕 `(0,0)`，左上角真正贴齐。独立只读审阅未发现需修复缺陷。
- 没有重启或注销用户电脑，实际登录后的启动仍需用户确认。
